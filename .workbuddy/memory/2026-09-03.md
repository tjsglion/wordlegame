# 2026-09-03

## 项目全局分析（/init）

对 wordlegame 做了完整架构分析。定位：多游戏 H5 单词游戏平台，生产域名 wordlegame.app，部署在 Cloudflare Workers（OpenNext）。

技术栈：Next.js 16.3.3 App Router + React 19.2 + Tailwind v4 + shadcn/ui(Base UI) + Drizzle ORM + Turso/libSQL + NextAuth v5 + next-intl + PixiJS(彩带)。`src/` 108 文件约 1.3 万行（其中 1611 行为生成词表）。

核心架构（项目最扎实的部分，改动前务必理解）：
- **服务端权威判定**：答案不出服务端。daily 查 `wordle_daily_puzzles` 表，practice 用 HMAC token（`src/lib/game/token.ts`，Web Crypto 以兼容 Workers）。客户端每次提交**完整 guesses 历史**，服务端 `evaluateGuess()` 全量重算，仅在结束后返回答案。
- **每日题双保险**：`daily-schedule.ts` 预生成 365 天写 DB + `worker.js` cron `5 0 * * *` 补期；DB 挂了降级 `pickDaily()`（xmur3 + mulberry32 确定性种子）保证全球同题。
- **防作弊**：`authoritative.ts` 用服务端答案重推 results 再落库，客户端伪造的胜负写不进去。localStorage 仅作离线缓存。
- **扩展点**：`src/games/registry.ts` 同时管元数据与 `gameLoaders`，`game-loader.tsx` 用 `next/dynamic(ssr:false)` 按 slug 代码分割。加新游戏只改 registry。
- i18n 中英 168 key 完全对齐；根布局刻意不重渲染（html/body 在 root layout）。

## 修复两个构建/校验坑（本次已做）

1. **陈旧路由类型** → package.json 新增脚本：
   - `typecheck` = `next typegen && tsc --noEmit`（自动重建类型再校验，可自愈）
   - `check` = `npm run typecheck && npm run lint`
   已实测：注入陈旧引用后裸 tsc 报 TS2307，`npm run typecheck` 自动修复并通过。
   `next typegen` 在沙箱 NODE_OPTIONS 下同样可用（只有 `next build` 的 Turbopack worker 会被 `--use-system-ca` 卡住）。

2. **沙箱构建失败** → 属环境注入而非项目缺陷，故只写进 README「🔧 Troubleshooting」，**未**把 `env -u NODE_OPTIONS` 硬编码进 package.json（会污染正常环境且不跨平台）：
   - Turbopack worker 拒收 `NODE_OPTIONS=--use-system-ca` → `env -u NODE_OPTIONS npm run build`
   - 批量删 `.next` 被安全策略拦 → `NEXT_DIST_DIR=.next-build npm run build`
   两条命令均已实测跑通（17 静态页，路由表正确）。

3. **顺带修**：`eslint.config.mjs` 的 `globalIgnores` 只忽略 `.next/**`，不忽略 `.next-build/**`——而后者正是上面绕法要写的目录。已补上，并用 A/B 对照验证（`.next-build` 下的问题被忽略，`src` 下同样内容仍被报告）。
